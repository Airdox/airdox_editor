## 3. Harte Arbeitsregeln

1. **Verschieben, nicht umschreiben.** Ein WP-06-Schritt kopiert Funktionsrümpfe wörtlich in ein neues
   Modul und macht die Abhängigkeiten zu typisierten Parametern. Kein Verhaltenswechsel im selben
   Commit. (`REFACTORING_PLAN.md`, WP-06 Migrationsregeln.)
2. **Ein Schritt pro Commit, ein Arbeitspaket pro PR.** Die bisherigen Commits zeigen das Muster:
   `83524b4` Schritt 1, `308a14c` Schritt 2, `e6d0896` Vorbereitung, `9cab64c` Schritt 3, `97fefba`
   Schritt 4, `9816f93` Schritt 7, `111b2ff` Doku. Jeder davon endet mit `tsc` grün + voller Suite.
3. **Keine Tests „grün biegen".** Fällt ein Textvertragstest aus, wird der *Pfad* im Test aktualisiert
   (die Datei ist umgezogen), nie der Vertrag selbst. Fällt ein Verhaltenstest aus, ist das ein Befund,
   kein Ärgernis – so wurde der Logger-Flush-Fehler gefunden (`REFACTORING_STATUS.md`, Kap. 3).
   `--fail-on-skip`-Läufe dürfen nicht durch Entfernen der Direktive „repariert" werden.
4. **Parallelarbeit meiden – und vorher prüfen.** Beide bisherigen Sitzungen kollidierten in
   `App.tsx`/`DetailWaveform.tsx` (18 Konflikte beim letzten Merge). **Aktuell offen: PR #77**
   (`arena/01a103e1-airdox-editor`, 60 Dateien) fasst `src/App.tsx`, `src/components/DetailWaveform.tsx`,
   `src/features/import/useTrackImport.ts` und `src/features/recorder/useRecorder.ts` an.
   Vor jedem WP-06-Schritt: `git fetch origin main && git diff --stat origin/main HEAD` **und**
   `gh pr list --state open`.
5. **Read-only-Garantien nicht antasten.** Original-Audio, XML, ANLZ und `master.db` werden nur gelesen.
   Konkret im Code: `protectedPaths` (`src/App.tsx:387–396`) darf beim Auslagern nicht verloren gehen,
   die Gates `master-db-gate`, `path-guard`, `rekordbox-gate-*`, `ripple-delete-original-integrity`
   bleiben unverändert grün. Ebenso: die Stem-Qualitäts-Gates und die ANLZ-Parität sind
   Schutzmechanismen, keine Aufräumkandidaten.
6. **Kein zweiter Positions-Pfad.** Wiedergabeposition kommt ausschließlich aus
   `src/state/transportStore.ts`; lesen über `getPositionSec()` oder `useThrottledPosition`.
   Ein `currentTimeRef` oder `setInterval` für Positionen in `App.tsx` ist ein Rückfall
   (heute: 0 × `requestAnimationFrame`, 1 × `setInterval` in `App.tsx:793` – das ist die
   Fortschrittsabfrage der Stem-Separation, keine Position).
7. **Nach jedem Schritt `npm run verify`** und – bei allem, was zeichnet – ein Screenshot gegen

### 5.1 SOFORT · `main` ist rot: Windows-Build schlägt fehl

**Befund (belegt, nicht vermutet).** GitHub-Actions-Lauf
[37171293293](https://github.com/Airdox/airdox_editor/actions/runs/37171293293) auf `main`
(Commit `c08e96f`), Job `build` (111344590922): die Schritte checkout → npm ci →
`rekordbox:native:ensure` → `npm run build` sind grün, **„Test-Suite ausführen" bricht ab**
(`Process completed with exit code 1`), der Installer wird deshalb gar nicht gebaut.
Der Vorläufer-Lauf [37171194975](https://github.com/Airdox/airdox_editor/actions/runs/37171194975)
(Merge PR #78, Job 111344331215) bricht an **derselben** Stelle ab: gleiche sechs grüne Schritte,
`X Test-Suite ausführen`, Installer übersprungen. `main` ist also seit zwei Merges durchgehend rot.

Annotation aus dem Job-Log:

```
X tests/stem-remote-worker-selftest.test.mjs fehlgeschlagen:
AssertionError [ERR_ASSERTION]: Abbruchpfad nicht ausgeführt – erwartet „während der Rechnung":
[STEM-REMOTE-WORKER] … abgebrochen (cancel.flag)  vor dem Start
[STEM-REMOTE-WORKER] … abgebrochen (cancel.flag)  whrend der Rechnung …
[STEM-REMOTE-WORKER] Selbsttest OK (Manifest, Idempotenz, Vollstndigkeit, Lease, …)
```

**Ursache, Kette für Kette:**

1. `colab/remote_worker.py` schreibt deutsche Meldungen auf stdout (14 Zeilen treffen allein auf
   `während`/`Vollständigkeit`/`abgebrochen` zu) und **setzt die Kodierung nie**
   (`grep -n "reconfigure\|PYTHONIOENCODING\|sys.stdout" colab/remote_worker.py` → nur `open(..., encoding="utf-8")`
   für *Dateien*, nichts für stdout).
2. Auf Windows ist stdout hier eine Pipe; CPython wählt dann die ANSI-Codepage (cp1252), nicht UTF-8.
3. `tests/stem-remote-worker-selftest.test.mjs:49` und `:52` sammeln die Ausgabe mit
   `out += chunk.toString()` – das dekodiert **UTF-8**. Das Byte `0xE4` („ä") ist allein kein gültiges
   UTF-8 und wird zu `U+FFFD`.
4. Die Marker-Liste in **Zeile 96** enthält `'während der Rechnung'`; die Assertion in **Zeile 97**
   findet sie im verstümmelten Text nicht. Der ASCII-Marker `'abgebrochen (cancel.flag)'` aus derselben
   Liste geht durch – genau das zeigt das Log. Zeile 95 (`/Selbsttest OK/`) ist ebenfalls ASCII-sicher
   und wird passiert.
5. Auf dem Linux-Runner ist stdout UTF-8, dort ist der Test grün – deshalb blieb es bis zum Merge unsichtbar.

**Nachgestellt und beide Fixes gegengeprüft** (Node 22 + Python 3, `PYTHONIOENCODING` als Stellvertreter
für die Windows-Codepage):

```
── Status quo (cp1252) ──      stdout-Kodierung: cp1252
  dekodiert : "… abgebrochen (cancel.flag) - w\uFFFDhrend der Rechnung"
  ASCII-Marker: true (geht)   Umlaut-Marker: false  ← bricht Zeile 96/97
── Variante A (PYTHONIOENCODING=utf-8, PYTHONUTF8=1) ──
  stdout-Kodierung: utf-8 → Umlaut-Marker: true
── Variante B (toleranter Regex) ──  /w\S{0,2}hrend der Rechnung/ → true in beiden Kodierungen
── Kontrolle UTF-8 (Linux) ──  beide Prüfungen true
```

Zusätzlich geprüft: `StringDecoder('utf8')` **allein** repariert den Fall *nicht* (es liefert ebenfalls
`U+FFFD`) – ein Stream-Dekoder hilft nur gegen Mehrbyte-Sequenzen, die über Chunk-Grenzen zerfallen.
Die Codepage muss an der Quelle stimmen (Variante A) oder die Assertion muss kodierungsunabhängig
werden (Variante B). Es ist **der einzige** Test, der Kindprozess-Ausgabe gegen einen Marker mit Umlaut
vergleicht: von 4 Tests mit `spawn()` haben die anderen Nicht-ASCII nur in ihren *Fehlertexten*
(`onnx-fixture-python-ort`, `rekordbox-gate-integration`), nicht im Vergleichswert.

**Herkunft der Datei – vorher `origin/main` prüfen.**
`tests/stem-remote-worker-selftest.test.mjs` stammt aus Commit `f09cacc`
(„fix(stems): Abbruch der externen Zerlegung greift jetzt – und ist sichtbar"), gemergt über
**PR #78** aus dem Branch `arena/01a104aa-airdox-editor` – also aus einer **Parallelsitzung**, nicht aus
der Refaktorisierung. `git cat-file -e origin/main:tests/stem-remote-worker-selftest.test.mjs` → vorhanden,
`git diff origin/main -- <datei>` → leer. Kein offener PR fasst die Datei an (`gh pr diff 77 --name-only`
enthält sie nicht). **Konsequenz:** Der Fix gehört in einen eigenen, kleinen PR mit klarem Betreff, nicht
in einen WP-06-Commit – sonst hängt ein Windows-Fix an einem Refactoring-Review.

**Variante A – Ursache beheben (empfohlen).** In `runCandidate`, `tests/stem-remote-worker-selftest.test.mjs:33`:

```js
      child = spawn(command, args, {
        cwd: ROOT,
        windowsHide: true,
        stdio: ['ignore', 'pipe', 'pipe'],
        // Python schreibt sonst in der Windows-ANSI-Codepage in die Pipe; Node dekodiert
        // unten UTF-8 – Umlaute kämen als U+FFFD an und die Marker-Prüfung (Z. 96) fiele um.
        env: { ...process.env, PYTHONIOENCODING: 'utf-8', PYTHONUTF8: '1' },
      });
```

Ergänzend gegen Chunk-Grenzen (Zeilen 24–25 und 49/52):

```js
import { StringDecoder } from 'node:string_decoder';
// …
    const decode = new StringDecoder('utf8');
    // …
    child.stdout.on('data', (chunk) => { out += decode.write(chunk); });
    child.stderr.on('data', (chunk) => { out += decode.write(chunk); });
    child.on('close', (code) => {
      clearTimeout(timer);
      out += decode.end();
      resolve({ spawned: true, code, out });
    });
```

**Variante B – Assertion kodierungsunabhängig machen** (ersetzt Zeilen 96–98; wirkt auch dann, wenn
irgendein anderes Python auf dem Rechner die Kodierung wieder umstellt):

```js
// Marker bewusst ohne Umlaut-Vergleich: schreibt Python in der Windows-ANSI-Codepage in die
// Pipe, kommt „ä" als U+FFFD an. Der Regex passt auf beide Kodierungen (nachgestellt).
for (const marker of [/abgebrochen \(cancel\.flag\)/, /w\S{0,2}hrend der Rechnung/]) {
  assert.match(result.out, marker, `Abbruchpfad nicht ausgeführt – erwartet ${marker}:\n${result.out}`);
}
```

**Empfehlung:** A + B zusammen (A beseitigt die Ursache, B macht den Test robust), plus derselbe
`env`-Block überall dort, wo künftig Python-Ausgabe gelesen wird.

**Nachweis nach dem Fix:** `gh workflow run windows-build.yml --ref <branch>` – das Workflow hat
`workflow_dispatch`, lässt sich also auf einem Branch starten, bevor gemergt wird. Lokal bleibt der Test
grün (er läuft hier in 2,4 s), beweist aber nichts für Windows.

DECL_PATTERNS = (
    r"\b(?:const|let|var)\s+([A-Za-z_$][\w$]*)",              # const x

    r"\b(?:const|let|var)\s*\[([^\]]*)\]",                    # const [a, setA]
    r"\bfunction\s+([A-Za-z_$][\w$]*)",                       # function f

    r"\bcatch\s*\(\s*([A-Za-z_$][\w$]*)",                     # catch (e)
    r"\bfor\s*\(\s*(?:const|let|var)\s+([A-Za-z_$][\w$]*)",   # for (const x of ...)
)

def strip_noise(src: str) -> str:
    src = re.sub(r"/\*.*?\*/", " ", src, flags=re.S)          # Blockkommentare
    src = re.sub(r"//[^\n]*", " ", src)                       # Zeilenkommentare
    src = re.sub(r"`(?:\\.|[^`\\])*`", "``", src, flags=re.S) # Template-Literale
    src = re.sub(r"'(?:\\.|[^'\\\n])*'", "''", src)           # einfache Strings
    src = re.sub(r'"(?:\\.|[^"\\\n])*"', '""', src)           # doppelte Strings
    src = re.sub(r"\.\.\.", " ", src)                         # Spread ≠ Eigenschaft
    return src

def main() -> int:
    if len(sys.argv) != 4:
        print(__doc__); return 2
    path, start, end = sys.argv[1], int(sys.argv[2]), int(sys.argv[3])
    lines = open(path, encoding="utf-8").read().splitlines()
    clean = strip_noise("\n".join(lines[start - 1:end]))

    referenced = set()
    for m in re.finditer(r"[A-Za-z_$][\w$]*", clean):
        name = m.group(0)
        before = clean[:m.start()].rstrip()
        after = clean[m.end():m.end() + 2].lstrip()
        if before.endswith("."):                              # foo.bar → Eigenschaft
            continue
        if before[-1:] in "{," and after.startswith(":"):     # { a: 1 } → Schlüssel
            continue
        referenced.add(name)

    declared = set()
    for pat in DECL_PATTERNS:
        for m in re.finditer(pat, clean):
            for part in m.group(1).split(","):
                name = part.split(":")[0].split("=")[0].strip().lstrip(".").strip()
                if re.fullmatch(r"[A-Za-z_$][\w$]*", name):

    print(f"  referenziert {len(referenced)} · im Block deklariert {len(declared)} · frei {len(free)}")
    print("  " + ", ".join(free))
    return 0

sys.exit(main())

1 `.tsx`. Ein neuer Logiktest, der Quellcode importiert, gehört deshalb in `.ts`; `.mjs` nur für
reine Node-/Prozess-Tests (Gate-Skripte, Python-Aufrufe).

### Falle 3 · `npm install --ignore-scripts`

Die Linux-CI installiert mit `npm ci --ignore-scripts` (`.github/workflows/quality-linux.yml`).
Grund: `better-sqlite3-multiple-ciphers` und `onnxruntime-node` bauen native Bindings, die für
Typcheck, Suite und Vite-Build **nicht** gebraucht werden. Wer lokal `npm ci` ohne den Schalter laufen
lässt, braucht Build-Werkzeugkette und verliert Zeit; wer die Bindings wirklich braucht
(Rekordbox-Runtime, ONNX), fährt `npm run rekordbox:native:ensure`. In dieser Sandbox:
`npm install --ignore-scripts` → 525 Pakete in 13 s, danach `npm run verify` grün.

### Falle 4 · Benchmark: Minimum aus 5 Läufen, nicht der erste Wert

`scripts/bench-waveform.mjs:37` – `REPEATS = AIRDOX_BENCH_REPEATS ?? 5`, plus Aufwärmlauf (Z. 90, 92),
berichtet wird das **Minimum**. Die ursprünglichen Rohwerte (18,29 / 180,22 / 2,539 ms) waren
JIT-Kaltstart-Artefakte und sind als Budgetgrundlage unbrauchbar (`budgets.json`, `$comment`).
Gemessen heute: 7,83 / 77,38 / 0,137 / 0,511 ms; Budgets 15 / 140 / 2 / 1,5 ms.
Einzelne Ausreißer nach oben sind normal – **nicht** sofort `budgets.json` hochsetzen.
Neue Referenz: `npm run bench -- --json`.

### Falle 5 · Deklarationsreihenfolge in `App.tsx`

Siehe Abschnitt 6, Punkt 5. Kurz: `useTransportControls` (Z. 1227) konsumiert Stem-Zustand (Z. 1242–1244),
`useTrackImport` (Z. 2295) konsumiert Import-/Analyse-Zustand. Blöcke lassen sich nicht beliebig
nach oben/unten schieben; `tsc` meldet „Block-scoped variable used before its declaration".

### Falle 6 · Windows-Codepage in Prozessausgabe

Der aktuelle `main`-Bruch (Abschnitt 5.1) ist der Prototyp: Kindprozess schreibt in der ANSI-Codepage,
Node dekodiert UTF-8, Umlaute werden zu `U+FFFD`, Marker-Vergleiche fallen um – **nur auf Windows**.
Regel: `PYTHONIOENCODING=utf-8`/`PYTHONUTF8=1` beim `spawn` setzen, Ausgabe über `StringDecoder`
sammeln, und Marker in Assertions ASCII-sicher oder per tolerantem Regex formulieren.
Ein `StringDecoder` allein reicht nicht (nachgestellt: liefert ebenfalls `U+FFFD`).

### Falle 7 · Ein SKIP ist kein Grün

Die 4 SKIPs sind Umgebungs-/Modellgrenzen: `onnx-fixture-python-ort` (onnxruntime),
`stem-isolation-gate-live` + `stem-separation-bsroformer-live` (PyTorch), `stem-real-audio` (Demucs).
Für Freigaben gelten `npm run test:stems:release`, `test:stems:gate`, `test:stems:real` mit
`--fail-on-skip` – dann zählt ein SKIP als Fehler. „79/79 grün" ersetzt diese Läufe nicht; sie sind
in dieser Sandbox nicht ausführbar (kein PyTorch, kein ONNX, kein Demucs, kein Windows).

### Falle 8 · Parallelsitzungen auf denselben Dateien

Belegt: PR #75 und PR #76 haben `App.tsx` + `DetailWaveform.tsx` gleichzeitig angefasst
(18 Merge-Konflikte, `REFACTORING_STATUS.md` Kap. 2a); der Merge von PR #78 brachte den Windows-Bruch
auf `main`; **PR #77 ist offen** und fasst `App.tsx`, `DetailWaveform.tsx`, `useTrackImport.ts`,
`useRecorder.ts` an (60 Dateien). Vor jedem Schritt:
`git fetch origin main && git diff --stat origin/main HEAD` und `gh pr list --state open`.
Absprache aus Kap. 11.7: während Phase 2 keine zweite Sitzung auf `App.tsx`/`DetailWaveform.tsx`.
